# 48-hour team plan

## Goal

Help an FBO manager plan staffing, test disruptions, and review a draft plan. Keep all demo data labeled synthetic.

## Delegate the work

| Member | Task | Deliverable |
|---|---|---|
| 1. Data | Check public traffic sources. Keep synthetic data as fallback. Label each input and source. | Clear data and source notes. |
| 2. Workload | Make task times and staffing assumptions easy to change. Ask an aviation mentor to review them. | Editable assumptions with unknown rules labeled. |
| 3. Roster | Build draft shifts from worker skills, availability, and hour limits. | Shift plan with coverage gaps. |
| 4. Disruptions and web | Add call-outs, arrival surges, and service delays. Compare both plans on the same inputs. | Web controls and fair plan comparison. |
| 5. Integration and demo | Connect the work, run checks, gather feedback, and rehearse. | Working demo, run instructions, and pitch. |

## Schedule

- **Hours 0–2:** Agree on the data fields and API before coding.
- **Hours 2–20:** Build tasks in parallel.
- **Hours 20–32:** Connect the parts.
- **Hours 32–42:** Test, fix issues, and get mentor feedback.
- **Hours 42–48:** Freeze changes and rehearse the demo.

## Demo must show

- Ordinary and event demand: low, medium, high.
- A draft staffing plan and uncovered work.
- One arrival surge and one staff call-out.
- Baseline and proposed plans tested on the same scenario.
- Manager review before any plan is accepted.

Do not claim synthetic results are real forecasts or savings. Do not dispatch staff or control aircraft. Treat breaks, rest, and other staffing rules as assumptions until an FBO expert checks them.
